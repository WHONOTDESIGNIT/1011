## Retiring the old tree

No dependency on any deploy: Netlify never sees the local path. The old checkout may be
retired once it holds nothing unique — both commands must be empty:

```powershell
git -C <old-tree> log --oneline --not origin/main   # empty = no unpushed work
git -C <old-tree> status --porcelain                # empty = nothing uncommitted
```

The freeze markers sit *outside* the repo (one level and two levels above it), so they do
not dirty that tree. Retire into a bundle + delete, don't leave the copy around: a second
tree with real history is exactly the disease this cleanup removed.

## Rules for changes

- Branch → push → the owner merges. Don't push to `main` directly.
- Never create files at the repo root; scratch work goes outside the repo.
- Build must be green: `cd astro; npm run build` → `✅ all checks passed`, 3,433 pages.
- Guard failures: read `ops/RUNBOOK.md` first, never edit the guard to pass.
- One-time per clone: `git config core.hooksPath ops/seo/git-hooks`.
- Machine-specific values (paths, credentials) belong in untracked files, not in commits.
- Scripts self-locate and configuration has exactly one source: `ops/seo/run-task.ps1`
  resolves its own directory and reads the `.env` beside it, and the scheduled tasks pass
  only `-File`. Do not add per-task environment variables or a `WorkingDirectory` — that
  is exactly where a stale path would hide after a move.
- Before treating a branch as merged, check its `head.sha`, not just `state=merged`:
  a branch can be merged and then pushed to again, and the later commits are then
  stranded outside `main` (this happened on 2026-10-21 with PR #92).
- `site-urls.txt` is generated by the build and stays out of git. The reverse proposal —
  track it again and keep it fresh from a pre-commit hook — is rejected: a sync hook can
  drift silently, while a build always writes the current list. (Rejected branch:
  `18c95a40`, 2026-10-21.)
- Deleting a branch: `git branch --merged main` is the rule, but cherry-picked work breaks
  it — the SHAs change while the content lands. For those, delete on **content
  equivalence** and record it: `git diff <old-tip> <new-tip> -- <paths>` must show only
  later additions, never deletions. Mapping goes in `_machine\closed-branch-shas-*.txt`.
- A push's exit code is not proof the remote moved. Verify with
  `git ls-remote origin <branch>` and compare the SHA; GitHub connectivity here drops
  intermittently and a retry can look like success.
- After a path moves, prove the imports by **resolving** them, not by counting `../`
  segments: a grep for three levels also flags the *correct* three-level import once the
  file sits one directory deeper. Resolve every specifier to a real path and check that it
  exists; that is the only check that survives a move.
- In PowerShell, `Select-String -Path` treats `[slug]` as a wildcard. Files with brackets
  in the name need `-LiteralPath`, or the check silently returns nothing and looks clean.
- **One writer per checkout.** Do not run git writes or builds in a working tree another
  agent is using. Concurrent writes put commits on the wrong branch (that happened on
  2026-10-21: a commit landed on someone else's checked-out branch) and make build results
  untrustworthy — and this repo's acceptance is "build green is true". If parallelism is
  genuinely needed: `git worktree add ..\work\<name> -b <branch>`, remove it when done
  (no dangling registrations), and accept that each worktree needs its own `node_modules`
  (~10 minutes). Default: take turns. If you see changes you did not make: don't touch
  them, don't stash, don't commit — report.
