**短い答え：** プロフォーマインボイスは、お金が動く前に買い手の財務チームが読む書類です。見積書と同じ商取引条件を記載し、地名を伴うIncotermを載せ、ユニット数とカートンを突き合わせる必要があります。崩れる項目は、どのプロジェクトでも同じです。

## PIが見積書より重要な理由

見積書は会話を始めるものです。プロフォーマインボイスは、買い手の財務部門が支払いを起案し、通貨を計上し、必要なら信用状を開設するために使うものです。

そこが基準を変えます。見積書は概算でも役に立ちます。項目が概算のPIは、支払いに関する問い合わせになり、メールのやり取りになり、手付金の遅れになります。

PIを出す前に、4つのことが成り立っていなければなりません。

- 価格、条件、範囲で見積書と一致している。
- すべての数量が突き合っている。ユニット数、カートン数、1カートンあたりの台数。
- Incotermは3文字のコードだけでなく、地名を伴って明記されている。
- クレームに影響する商取引条件、とくに保証が記載されている。

## 項目の一覧

| 項目 | 書くべき内容 | 崩れ方 |
|---|---|---|
| 当事者 | 双方の法人名と住所 | 片方が商号だけで、法人名がない |
| 番号と日付 | PIの参照番号と発行日 | 参照番号がなく、誰も支払いと照合できない |
| 有効期間 | 価格が有効な期間 | 期限がなく、買い手が予算を立てた後に値上げされる |
| 製品 | モデル、説明、関税コード | 説明だけで、型番がない |
| 数量 | ユニット数、および1カートンあたりの台数を伴うカートン数 | ユニット数だけで、フォワーダーにカートン数がない |
| 価格 | 単価、通貨、合計 | 通貨が文脈からの推測になる |
| Incoterm | 条件**および**地名 | 港のない「FOB」 |
| 支払い | 手付金の比率、残金のトリガー | 何の70%なのか、いつなのかを書かない「30/70」 |
| リードタイム | どの時点から数えた日数か | 起点を書かない「25日」 |
| 梱包 | カートン数、寸法、総重量と正味重量 | まだ存在しないパッキングリストに任せる |
| 保証 | プラットフォームごとの条件 | カタログにはあり、ここにはない |
| 銀行口座 | 口座、SWIFT、売り手と一致する受取人名 | 受取人名がインボイスと違う |

## 発注を止める3つの項目

**地名のないIncoterm。** 「FOB」は条件の半分です。FOB ShenzhenとFOB Ningboは別の価格であり、買い手は港がなければ着地コストを計算できません。同じことはDDPにも当てはまります。地名は納品先住所であり、価格を条件そのものより大きく変えます。

**ユニット数と突き合わないカートン。** 1カートン18台で504台の発注は、28カートンです。PIが504台と言い、後からパッキングリストが26カートンと言えば、コンテナを予約する前に誰かがその差を説明しなければなりません。そして答えはたいてい、記載されなかった予備の台数です。その予備の行をPIに書いてください。

**届かない保証条件。** 2年に触れた見積書と、何も触れないPIは、保証を契約から落とします。18か月後にクレームが来ると、買い手は見積書を差し出し、供給者はPIを差し出します。

## 読み違えられないように書く支払条件

「30/70」は1文に収まる略記であり、議論を生みます。3つの事実として書いてください。

- 手付金の比率と通貨、そしてそのトリガー。PIへの署名、または発注書です。
- 残金の比率とトリガー。出荷前、船荷証券のコピーと引き換え、または到着時です。
- 銀行手数料を誰が、どちら側で負担するのか。

トリガーは比率より重要です。残金70%の「出荷前」は、70%の「書類と引き換え」とは別の取引であり、ほとんどのメールではどちらも70%と書かれています。

## 関税コードを置く場所

ブローカーが申告するとしても、関税コードはPIに載せます。買い手の財務チームが関税の見積もりに必要とし、買い手の通関ブローカーが貨物の移動前に必要とするからです。

これは自分たちを守ることにもなります。コードと、それに整合する品名を載せたPIは、後から分類を変えられにくくなります。コードがまだ確定していない場合は、欄を空欄のままにするのではなく、申告する予定のコードを書き、ブローカーの確認を条件とする旨を添えてください。

## 当社がPIに載せるもの

当社は、法人名、参照番号と有効期間、モデルと関税コード、予備の行を含むユニット数とカートン数、Incotermと地名、トリガーを含む支払いの分割、手付金の受領時点から数えたリードタイム、梱包データ、プラットフォームごとの保証条件、そして受取人名が売り手と一致する銀行口座情報を載せてPIを発行します。

当社がしないのは、合意されていない見積書からPIを発行すること、そして見積書が未確定のままにした項目を抱えたPIを外に出すことです。

そのうえで発注に輸出書類一式が必要なら、[すべてのカートンに同行する5通りの書類](/blog/export-documents-ipl-shipment)が併読先であり、[実測CBMが計算CBMに勝つ理由](/blog/carton-cbm-freight-ipl)が、PIの梱包欄が反映すべき容積を説明します。価格の背景にある商取引条件については、[保証条件](/blog/ipl-warranty-terms)と[OEM/ODMのプロセス](/services/oem-odm)が、最も多く抜け落ちる2つの項目を扱っています。
